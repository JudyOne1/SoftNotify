# 阶段 7 调研与改造方案（模式重构 × 统计/历史入口 × 区域可视化 × 全屏免打扰）

_2026-08-29 起草。四项均来自所有者实测反馈。_

## 1. 「模式」功能重构（现有快照模型用着别扭）

**现状问题**：模式 = 整份配置快照。用起来别扭的根源：① 模式内容不可见（应用前不知道它会改什么）；② 改一个提醒要「应用模式 → 去改 → 重新保存模式」三步舞；③ 「保存当前为模式」语义模糊（改了当前配置但模式不同步）。

**业界调研**：
- **iOS 专注模式（Focus）**：模式是「容器」而非快照——每个模式里直接勾选允许哪些 App/联系人，编辑模式即所见即所得，无「应用/保存」步骤（系统设置 → 专注模式）
- **游戏工具（GeForce Experience / AMD Adrenalin）**：按游戏自动套用画质配置文件，配置文件直接列出各项参数值
- **OBS 场景**：场景 = 引用一组源的容器，切换场景只是改变引用集合，源本体只有一份

**改造方案（推荐「引用式容器」模型）**：
- 模式不再是快照，而是**引用**：`Profile = { id, name, itemIds: string[], zone/sound 等外观覆盖? }`
- 应用模式 = 把该模式引用的提醒项设为启用、其余禁用（提醒项本体只有一份，编辑永远在提醒分区，所有模式共享）
- 模式编辑页：每个模式一张卡，卡内直接勾选「包含哪些提醒项」——所见即所得，无三步舞
- 迁移：现有快照模式按「应用快照后哪些项启用」反推出引用集合（一次性迁移）
- 托盘切换逻辑不变；不含 reminder 的字段（主题/音区）从模式中移除，保持模式语义单一=「哪些提醒在跑」
- **成本：中**（数据模型+迁移+模式编辑 UI 重做）

备选（小修）：保留快照，加「更新模式为当前配置」按钮 + 模式卡显示内容摘要。成本低但三步舞仍在。

## 2. 统计/历史入口统一进设置

**方案**：托盘「打卡统计」「弹幕历史」两个独立窗口移除，改为设置窗口侧栏的两个分区（📊 统计、🕘 历史）：
- StatsApp/HistoryApp 的内容改造成分区组件嵌入 SettingsApp（顺带完成 Tailwind/拟物统一，清掉旧 settings.css）
- 托盘保留「打卡统计」快捷入口吗？——建议移除，托盘只留高频操作（提醒/补打/会议/暂停/设置）
- **成本：低**，顺带清理技术债（settings.css 退役、窗口数 5→3）

## 3. 弹幕区域自定义可视化

**现状问题**：两个百分比滑杆（开始/结束）不直观——用户脑中是「屏幕的哪一块」，不是两个数字。

**业界参照**：视频剪辑的时间轴拖拽手柄、手机亮度调节的区域选择、OBS 的源拖拽。通用模式 = **在缩小版屏幕示意图上拖两个手柄**。

**改造方案**：设置「弹幕」区自定义模式下显示一个 **16:9 迷你屏幕示意**：
- 区域用半透明高亮块表示，上下各一个拖拽手柄（类似视频裁剪）
- 拖动实时更新 zoneStart/zoneEnd，预设 chips（全屏/上半屏/顶部30%）保留在旁边一键套用
- 实现：纯 React + 指针事件（pointerdown/move + capture），约 120 行，无依赖
- **成本：中低**

## 4. 全屏免打扰（观影/游戏自动静默）

**调研结论**：Electron 无内置 API 探测**外部**应用全屏；[get-windows](https://github.com/sindresorhus/get-windows)（sindresorhus 官方，active-win 更名，v9.2.3 2025-08 更新，Win7+/macOS/Linux）返回前台窗口 bounds/owner/title——**前台窗口矩形覆盖任一显示器 ≥98% 即视为全屏**。

**行为定义**：
- 轮询 3s；全屏中 → 一切弹幕静默（与会议模式同级），托盘 tooltip 显示「全屏应用中」
- 恢复窗口化后自动解除；检测异常静默视为非全屏
- 浏览器全屏视频 ✓、无边框窗口游戏 ✓、独占全屏游戏 ✓（前台窗口 bounds 仍为全屏）
- 多显示器：任一显示器被全屏占用即全局静默（观影场景符合预期）
- 设置项「全屏应用时自动免打扰」**默认开**（这正是所期望的默认行为）
- 实现选型：get-windows（维护好、跨平台、ESM 动态导入）✓ 推荐；koffi FFI 手写（少一个依赖但自维护）；PowerShell 轮询（太重）
- **成本：中低**
